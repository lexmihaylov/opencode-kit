# Usability Validation

- Define the target user, realistic task, starting context, success criteria, and observable failure signals before testing.
- Use scenarios that measure task completion and comprehension, not preferences alone.
- Keep test scripts neutral; ask participants to think aloud without teaching the intended path.
- Capture evidence for where people hesitate, misunderstand labels, abandon a path, or recover from errors.
- Rank findings by task impact, frequency or confidence, and severity; distinguish evidence from design hypotheses.
- Recommend the smallest flow, content, or interaction change that addresses each finding, then identify what should be retested.
- Use `testing` for software behavior and automated checks; this skill validates human task success. See the [GOV.UK design guidance](https://www.gov.uk/service-manual/design) for inclusive, task-focused service design principles.
