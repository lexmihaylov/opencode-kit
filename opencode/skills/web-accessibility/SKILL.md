# Web Accessibility

- Use semantic HTML first; give every control an accessible name, clear purpose, and appropriate state and error feedback.
- Ensure the complete critical task works with keyboard-only input, visible focus, logical focus order, and no focus traps except managed modal dialogs.
- For forms, associate labels, instructions, validation, and errors; preserve entered values and make recovery clear.
- For dialogs and custom widgets, follow an established accessible interaction pattern rather than inventing keyboard behavior.
- Check contrast, zoom, narrow-width reflow, target size, and reduced-motion behavior for changed experiences.
- Report audit findings with affected task, evidence, user impact, severity, and the relevant criterion or pattern; distinguish observed defects from unverified risk.
- Do not claim legal compliance or conformance certification. Use [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/) and [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/) to select applicable criteria and patterns.
