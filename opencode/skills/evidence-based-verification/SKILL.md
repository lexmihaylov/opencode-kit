# Evidence-Based Verification

- Tie every completion claim to a specific acceptance criterion, behavior, or contract.
- Run the smallest relevant check first; expand verification only for changed risk, failures, or missing evidence.
- Distinguish checks that passed, checks not run, and assumptions; never imply unrun verification succeeded.
- Prefer fresh evidence from the changed code, targeted tests, builds, type checks, or reproducible manual checks.
- If verification is blocked, state the blocker, the affected criterion, and the residual risk.
- Do not substitute style checks, compilation, or unrelated test suites for behavioral evidence.
